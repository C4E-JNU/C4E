# 数据核查（data-audit）

本技能只属于 `verifier` 档案（`backend/agents/verifier/skills/`）。
主智能体看不到它 —— 这正是「子智能体自带技能目录」的用途：核查口径集中在核查员自己手里，
不会因为主控换了提示词而漂移。

## 判定四档

| 判定 | 条件 | 处理 |
|---|---|---|
| 支持 | 原文有明确字串，数值/单位一致 | 记 `PASS`，附 text_quote |
| 部分支持 | 数值对但单位/条件（pH、温度、时间）缺失或不符 | 记 `PARTIAL`，写明缺什么 |
| 不支持 | 原文无据，或数值明显不同 | 记 `FAIL`，给建议修正值 |
| 无法核对 | 找不到对应原文（可能引用的是别篇/别章节） | 记 `NEED_CHECK`，**不要猜** |

## 硬纪律

1. **引文必须能在原文搜到**：`text_quote` 是原文子串，不做同义改写、不补标点。
2. **数字带单位才算数**：`mg/L`、`g/L`、`℃`、`min`、`min⁻¹`；单位不一致先换算，并在结论里写出换算过程。
3. **含糊表述不算证据**：`about`、`nearly`、`~`、`a few` 一律不算定量依据，标 `PARTIAL` 并说明。
4. **一量两值不合并**：同一指标在正文/表格/图注出现两个值时，两个都列，各带出处，交给主控裁决。
5. **宁缺毋滥**：拿不准就 `NEED_CHECK`；谎报 PASS 比漏报的代价大得多。

## 输出格式

```
条目 | 判定 | 原文字串 | 建议值/说明
```

末尾按统一约定附状态行：

```
【STATUS】ok|partial|failed 【MISSING】缺什么（无则 none） 【CONFIDENCE】0~1
```

## 常见坑

- **表格数值以 `TableN.txt` 为准，图注以 `FigureN.txt` 为准**：正文与表格冲突时先怀疑 OCR，而不是直接判 FAIL。
- **Section 编号错位**：有些 PDF 的章节号是图片，正文里搜不到 → 把该条标 `NEED_CHECK` 并说明，不要退化成「用常识判断」。
- **不要为了凑数而重复列同一条**：同一数据在结果段与摘要段各出现一次，只算一条，出处写两处即可。
