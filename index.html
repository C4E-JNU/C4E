控制随机性：较低值更确定性，较高值更有创造性
模型记住的对话轮次数量
每次请求发给模型的 max_tokens：单次回答最多能生成多少 token，超了会被服务端截断。
DeepSeek 官方合法范围 1~393216（384K）；不传时默认「非思考 8K / 思考 64K」。思考模式下思维链也占这份额度，所以设太小会让正文很短（甚至为空）。
⚠️ 填大不会让回答变长（何时停由模型决定），但超过服务端真实上限会被 400 拒收。想要长代码/长报告，建议 64K 以上。
该值还参与「清理触发线」计算（用来预留输出空间）。回答被截断且正夹着工具调用时，本轮会中止并提示调大它。
模型一次最多能接收的 token 数（hard limit，由模型本身决定，如 256K / 1M）。
它只用于计算「什么时候开始清理旧工具结果」，本机不会因为超过此值而报错、截断或中断对话；真的超过模型能力时，只由模型服务端报错（那才是真的超上下文）。
👉 填真实值最稳：填小 → 更早开始清理（保守，不报错）；填大 → 更晚清理，超了交给服务端。
👉 本值不与所选模型自动绑定，请按实际调用的模型填（256K 填 262144，1M 填 1048576）。
发送给模型的 token 估算量（或 API 真实用量）达到此值时，开始把较早的工具结果替换成占位符——只动工具结果，你和 AI 的正文、技能正文永不清。
0 = 自动：(上下文窗口 − 输出预留) × 75%，并保底 ≥ 1024。
⚠️ 设得过大＝几乎不清理，上下文会一路涨到模型窗口，最终由服务端报错；设得过小＝频繁清理（可能每轮都在清旧工具结果）。
当前发送给LLM的Token数超过此值时，界面红字加粗警告（仅提示，不影响输入）
