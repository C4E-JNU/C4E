# 步骤八：单位复核（纯 LLM，无脚本）

> **2026-10-09 起改版**：单位化已在步骤七填充时由 LLM 完成（换算表内嵌两个填充档案，直接产三元组）。
> 本步是**换主体的独立复核**：派 `fenton-normalizer`（复核模式）只读复核 `06_schema.json` 的全部【数】字段——
> 核实三元组合法性、逐条对照规范单位表查换算、补充缺失单位——**全程无脚本**
> （脚本对含条件从句的字符串易判错，确定性换算由 LLM 带上下文做完，复核再换一双眼睛）。
> 下方「附」保留旧批次（「数值+单位」字符串口径）的脚本三段式流程；脚本字段清单
> （`CATALYST_NUM_KEYS` 等）仍是填充档案【数】标注的参照来源。

> 前置：步骤七对账门 PASS（`06_schema.json` 就绪，【数】字段已是三元组）
> 执行：**派 `fenton-normalizer`（复核模式，按节点分批）→ 主控落盘修订清单 → 修订闭环**
> 产出：`06c_unit_review.json`（复核记录 + 修订清单）+ 修订后的 `06_schema.json`

## 派发（按节点分批，一个 C 或一个 E 一批）

```
delegate_task(tasks=[
  {"profile": "fenton-normalizer",
   "goal": "复核 C1 全部【数】字段三元组：单位白名单 / 换算正确 / 缺失补充；只回修订清单",
   "context": "<论文文件夹>/datamining 目录路径；字段清单 backend/agents/fenton-schema-catalyst/system.md"},
  # E1、E2… 各一条，字段清单换 fenton-schema-experiment/system.md
])
```

## 复核员查什么（五类，细节见其 system.md）

① 三元组合法（value 纯数字或 null、unit 在白名单、raw 非空）② 换算正确（逐条对照规范单位表：
K→℃、h→min、mg/L↔g/L 笔误）③ unit 缺失按字段语义补（`unit_inferred`）④ 不可换算单位保留原样
（At% + 注明）⑤ 【文】字段误包三元组、levels metric_value 与 stability 同口径。

## 主控收口

1. 逐节点回报合并落盘 `<论文夹>/datamining/06c_unit_review.json`；
2. **修订闭环**：`revisions` 交回对应填充员档案实例 → 只回受影响字段的修正片段 → 主控重装配
   `06_schema.json`（与步骤七同一装配机制）；`revisions = 0` 直接进步骤九；
3. `uncertain` 条目记台账，交步骤九 auditor 参考。

## 核验

1. `06c_unit_review.json` 可解析，`checked` 统计与该节点【数】字段数自洽；
2. 每条 revision 带 before/after/reason，`after` 的 value 纯数字、unit 在白名单、raw 与 before 一致；
3. 抽 2 条修订核对 `06_schema.json` 已实际更新；
4. `uncertain` 不得空缺不报。

## 附：旧批次脚本流程（仅「数值+单位」字符串口径批次使用）

## 为什么不是纯脚本，也不是纯 LLM

纯脚本对简单串（`"12.5 mg/L"`）够用，难串必拍错：条件从句抢值（`"TGA 450-600 ℃"`）、
化学式里的数字（`N2` / `Fe3O4`）、多口径并存（`">100 nm，另有两处约 40、约 70 nm"`）、
不可换算单位（`At%` vs `wt%`）—— 这些要看上下文才能定，脚本没有上下文。
反过来纯 LLM 会引入「同一份数据两种写法」。所以：**确定性初判走脚本，语义定稿走子智能体，校验落盘回脚本**。

## ① 初判（脚本）

```
python step9_numeric_normalize.py <论文夹 或 批次根> --prepare
```

产 `<dm>/06b_numeric_tasks.json`：

- `tasks[] = {id, field, node_type, raw, draft, flags}`；`draft` = 机械初判（**可能错**，供参照）；
- `flags ∈ {unparsed, ambiguous, unit_inferred, converted, multi}`，**flagged 排在最前**；
- 同时产 `06b_numeric_draft.json`（全量草案，结构同 06_schema）。

## ② 定稿（子智能体 `fenton-normalizer`）

```
delegate_task(tasks=[
  {"profile": "fenton-normalizer",
   "goal": "对 C1 的数值字段定稿（只回本批 id）：值 / 单位 / 原文 / 依据",
   "context": "<论文文件夹>/datamining 目录路径；待判清单见 06b_numeric_tasks.json；只回 id 以 C1. 开头的条目"},
  # 其余批次：C1.E1.（含变量/稳定性）／ C1.E2. …
])
```

- **按节点分批**（一个 C 节点、或一个 E 节点一批）—— 单实例输出 ≤ 12000 字符，整篇一次必被截断；
- **变量水平项（v2）**：id 形如 `C1.E1.V1.L2.level_value` / `…L2.metric_value`（一个水平一对 ——
  水平值与该水平的指标同层）；**逐条都要判**，漏判即该水平停在机械初判、图谱里就查不出「pH=3 的去除率」；
- 判据、单位白名单、规范单位表、id 命名与回报 schema 见 `backend/agents/fenton-normalizer/system.md`（**唯一载体**，本文件不重复）；
- 主控只核：本批 id 全覆盖、`unit` 在白名单或 `null`、`value` 类型合法、`unparsed` 条目带 `basis`。

## ③ 校验落盘（脚本）

```
python step9_numeric_normalize.py <论文夹 或 批次根> --from-agent <回报.json>
```

- **合并**：agent 给到的用 agent 值；未覆盖的 id 保留机械草案并标 `source: mechanical`；
- **raw 一律取 `06_schema.json` 源串**（LLM 不得改写原文；脚本强制执行）；
- **校验门**（任一不过 → `gate=FAIL`、进程 exit 1）：
  `unknown_id`（id 不在清单）／`bad_field`（键名不符清单）／`bad_unit`（单位越界）／
  `bad_value`（值类型非法）／`structure`（树结构与 06_schema 不一致）／`bare`（仍有裸字符串未标准化）；
- **只提示不 FAIL**：`not_canonical`（单位非该字段规范单位，如 At% 不可换算）、
  `unit_inferred`（源串没给单位、按字段语义补齐）。

## 产物

| 文件 | 内容 |
|---|---|
| `06b_numeric_schema.json` | **成品**：树结构与 06_schema 一致；数值字段 = `{value, unit, raw}`（另可带 `range` / `uncertainty` / `qualifier` / `converted` / `basis` / `source`） |
| `06b_numeric_stats.json` | 计数 + `source_counts`（agent / mechanical）+ `flags` + `issues` + `verify` |
| `06b_numeric_review.json` | 交步骤九的复核清单（unparsed / ambiguous / unit_inferred / 不可换算） |
| `06b_numeric_tasks.json` · `06b_numeric_draft.json` | 中间产物（留档） |

**不回改 `06_schema.json`**（原文留痕，可回溯）。

**兜底路径**：不带参数直接跑 → 纯机械落盘（`source=mechanical`），用于子智能体不可用时快速验证；
**正式跑批必须走 --prepare / --from-agent**。

## 核验

1. `gate=PASS`（无 unknown_id / bad_unit / bad_field / bad_value / structure / bare）；
2. 树结构与 `06_schema.json` 一致（催化剂 / 实验 / 变量节点数相同）；
3. 目标字段**全部成三元组**，无残留裸字符串；
4. 单位全部落在白名单内（源于源串或字段语义兜底，后者记 `unit_inferred`）；
5. `06b_numeric_review.json` 的 `unparsed` / `ambiguous` 逐条可解释（长句、定性、多口径），清单交步骤九；
6. `stats.source_counts.agent + stats.source_counts.mechanical` = 标准化字段总数。
