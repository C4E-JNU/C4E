# 步骤九：成品查验（终检）

> 前置：步骤七对账门 PASS（新批次成品 = `06_schema.json`，三元组内联；旧批次 = `06b_numeric_schema.json`）
> 执行：**派 `fenton-auditor`，每篇 1 个实例**；主控只汇总，不参与判读
> 目的：提取工作流已跑完，换一个独立主体、拿全链成品复核一遍，确认结果可信后再入图谱

## 为什么派子智能体（而不是主控自检）

前八步的产出都是「自己做的」——同一主体自检等于自批作业。
终检员只拿成品、**不看中间过程**，上下文独立：查得出主控看不见的口径漂移。
它**只读不写**，修复决定权在主控。

## 派发

```
delegate_task(tasks=[
  {"profile": "fenton-auditor",
   "goal": "对 <论文文件夹名> 的提取成品做终检，产出 08_audit.json",
   "context": "<论文文件夹>/datamining 目录路径 + 字段清单文件路径 backend/agents/fenton-schema-catalyst/system.md 与 backend/agents/fenton-schema-experiment/system.md；独立复核，不回改任何文件"},
])
```

**每篇一个实例**（上下文隔离，互不污染）；多篇可并行派多个实例。

## 查什么（五类，逐类给结论，不得略过）

| 类 | 查法 | 判为 issue 的条件 |
|---|---|---|
| ① 字段合规 | 成品（`06`，旧批次 `06b`）键名 vs 45 / 41 清单逐字比对（**清单来源**：`backend/agents/fenton-schema-catalyst/system.md`（45）与 `backend/agents/fenton-schema-experiment/system.md`（41+6），合订兜底本 `backend/agents/fenton-schema/system.md`；技能内不重复维护，派发 context 必须给出路径）；单位是否在归一表内；**【数】字段是否已成 `{value, unit, raw}` 三元组**（字段清单有【数】/【文】标注；裸字符串仅对【数】字段算 issue，【文】字段字符串合法）；旧批次再对照 `06b_numeric_review.json` 复核 `unparsed` / `ambiguous` 条目（新批次无此清单，跳过） | 键名不符 / 单位越界 / 【数】字段裸串 / 三元组缺 `unit` 或 `raw` |
| ② 值-源一致 | **抽样**回正文 `00_full_cleaned.md` 与图账 `04_verified_image_data.json` 对数值 | 超 5% 量程差 |
| ③ 曲线合理 | 点数 ≥3、x 单调、y 在量纲内、`metric` 与图注一致 | 违反任一项 |
| ④ 账目完整 | `07_contradiction_ledger` 的候选条数 = `04_discrepancy_ledger` + `04b`（去重后，**不含 Q1/Q2**——那些在 `04c_errata.json`）**+ 步骤 5B 裁决追加条**（若有）；每条带 `evidence_source`（四个合法值内）与 `adopt_reason`；`severity` 已由**步骤 5B** 回填（**无空值、取值须 ∈ A/B/C/D/E**；`E`=其他·无法归类，一律带 `needs_human_review=true`） | 缺项 / 空理由 / `evidence_source` 越界 / 出现旧 `category` / `severity` 为空或越界（出现 `unknown` 亦算越界） |
| ⑤ 图谱预检 | ① 06b 引用完整性：experiment 的 `catalyst_id` 必须存在、variable 挂到存在的实验、`pollutant_name` 非空、曲线有 `ref`/`points`、id 无重复；② 用 `graph_query` 查库里是否已有**同义污染物节点**（→ 合并信号）与**同族催化剂**（→ 聚合键） | 悬空引用 / 空名 / id 重复 |

**抽样纪律**：② 每类节点至少抽 1 条、实验类抽 ≥3 条；每条附**原文引文**（不得只写「一致」）。
**只报问题、不改数据**：修复由主控按 issue 决定是否回退上游步骤。

## 回报格式

回报 JSON 的**字段定义与示例见** `backend/agents/fenton-auditor/system.md`（唯一载体，本文件不重复）。
主控只核：五类都有 `checked=true` 与 `pass`、`verdict=pass` 且 `blocker=0`、每条 issue 带原文引文与定位。
`severity`：`blocker`（必须回退修）/ `major`（口径不一致）/ `minor`（记录待查）—— **终检口径，与矛盾 A–D 无关**。

## 主控收口

1. 逐篇落盘 `<论文夹>/datamining/08_audit.json`；
2. 汇总 issues 按 severity 排序：**blocker > 0 → 该篇不得进步骤十**，回退对应上游步骤修完重跑终检；
3. major 记入台账，minor 记录待查。

## 核验

1. 每篇 `08_audit.json` 可解析，五类都有 `checked=true` 与 `pass`；
2. `verdict=pass` 且 `blocker=0` 才放行进步骤十；
3. ② 的每条 issue 带**原文引文与定位**（图号 / 节号）；
4. 未改任何上游文件（`06b` / `07` / `04` 的 md5 与派发前一致）；
5. 旧批次：`06b_numeric_review.json` 的 `unparsed` / `ambiguous` / `unit_inferred` 条目**逐条**已有结论
   （采纳 / 回退 / 待人工）；新批次无此清单，本项跳过。
