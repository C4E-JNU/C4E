# 步骤一：文献筛选（体系判定 + 查重）

> 前置：用户给的文献，可能是 PDF，也可能是已解压好的文献文件夹
> 执行：派 `fenton-screener`（只读回传，主控落盘）

**先确定用户给的路径在哪**。已解压的文献文件夹形如：

```text
<论文文件夹>/
├── full.md                  MinerU 解析的原文 markdown
├── images/                  MinerU 切出的散图（hash 文件名 jpg/png）
├── *_content_list.json      MinerU 索引（图注 ↔ 图片映射）
└── *_origin.pdf             原始 PDF（后续步骤使用，本步不动）
```

把这个 PDF 或 `full.md` 的路径交给专有的 `fenton-screener` 子智能体，判两件事：文献是否符合非均相 Fenton 体系、图谱中是否已有该篇。

**只给这一篇的全文**，不给设计报告 / 步骤文档 / 他篇论文 / 批次台账 / 历史结论（旁证会把先验带进判决）。

多篇可同时派多个 `fenton-screener`（同档案可多实例并行）；单个子智能体不宜超过 5 篇，否则上下文会爆炸。

## 派发

```text
delegate_task(tasks=[
  {"profile": "fenton-screener",
   "goal": "筛选这篇文献：判体系是否符合非均相 Fenton、判 neo4j 知识图谱中是否已有该篇数据，给 pass/skip/manual 与证据",
   "context": "<该篇的 PDF 或 full.md 路径>"}
])
```

## 子智能体回报格式

回报 JSON 的**字段定义与示例见** `backend/agents/fenton-screener/system.md`（唯一载体，本文件不重复）。
主控只看三样：`decision`（pass/skip/manual）、`system.evidence`（非空）、`duplicate.checked` 三路都有值。

## 主控收口

1. 逐篇落盘 `00_screening.json`，补 `screened_at`、`screened_by`。
2. 按 `decision` 放行：`pass` → 进步骤二；否则该篇到此结束。

## 核验

1. 每篇 `00_screening.json` 存在且可解析。
2. `system.evidence` 非空；`skip` 的 `reasons` 非空且含原文证据。
3. `duplicate.checked` 三路都有值（连不上必须写 `"unavailable"`，不许留空或默认 false）。
4. 汇总 `by_decision` 计数与实际一致。

## 下一步

核验通过 → 步骤二：解析与归档（`references/步骤二_解析与归档.md`）。
